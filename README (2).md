# Spider Deploy Bot

ربات تلگرامیِ چندکاربره که پنل‌های موجود توی کاتالوگ (فعلاً Spider Panel و 3x-ui) رو
روی اکانت Railway هرکسی که استفاده‌اش می‌کنه دیپلوی می‌کنه، TCP Proxy می‌سازه، پنل‌ها رو
آپدیت نگه می‌داره، و می‌تونه از خودش کپی جدید بسازه.

## معماری: یک کد، دو پلتفرم

منطق اصلی توی `bot-core.js` هست و به هیچ API مخصوصِ یک پلتفرم وابسته نیست. دو تا
لایه‌ی نازک روش سوارن:

|فایل                        |پلتفرم                         |ذخیره‌سازی                                            |
|----------------------------|-------------------------------|-----------------------------------------------------|
|`worker.js`                 |Cloudflare Workers (سرورلس)    |Workers KV                                           |
|`server.js` + `package.json`|Railway (Node.js، پروسه‌ی دائمی)|فایل JSON محلی (نیاز به Volume برای persistent موندن)|

هر دو از همون `bot-core.js` استفاده می‌کنن، پس هر تغییری توی منطق ربات فقط یه بار لازمه اعمال بشه.

## نصب روی Cloudflare Workers

### ۱. پیش‌نیاز

```bash
npm install -g wrangler
wrangler login
```

### ۲. ساخت ربات تلگرام

با [@BotFather](https://t.me/BotFather) یک بات بساز و توکنش رو نگه دار. `Chat ID` خودت
رو هم از [@userinfobot](https://t.me/userinfobot) بگیر.

### ۳. push کردن این پوشه به یک ریپوی GitHub خودت

قابلیت Clone Bot زمان اجرا `bot-core.js` و `worker.js` رو از GitHub می‌خونه، پس
`wrangler.toml` → `SOURCE_REPO` باید به همون ریپو اشاره کنه:

```toml
SOURCE_REPO = "yourusername/spider-deploy-bot"
```

### ۴. ساخت KV namespace

```bash
wrangler kv namespace create BOT_KV
```

`id` خروجی رو داخل `wrangler.toml` جایگزین `REPLACE_WITH_KV_ID` کن.

### ۵. Secret ها

```bash
wrangler secret put BOT_TOKEN
wrangler secret put ADMIN_CHAT_ID
wrangler secret put WEBHOOK_SECRET     # یه رشته‌ی رندوم، مثلاً: openssl rand -hex 16
```

### ۶. دیپلوی و ثبت وبهوک

```bash
wrangler deploy
```

بعدش آدرس Worker رو با `/setup` یک‌بار باز کن (مثلاً
`https://spider-deploy-bot.yourname.workers.dev/setup`) تا وبهوک ثبت بشه.

## نصب روی Railway (Node.js)

اگه ترجیح می‌دی بات به‌جای Cloudflare روی Railway (به‌صورت یک پروسه‌ی دائمی) اجرا بشه:

1. **New Project → Deploy from GitHub repo** و همین ریپو رو انتخاب کن. Railway خودش
   `package.json` رو تشخیص می‌ده و `npm start` (یعنی `node server.js`) رو اجرا می‌کنه.
1. Environment Variables ست کن: `BOT_TOKEN`, `ADMIN_CHAT_ID`, `WEBHOOK_SECRET`,
   `SOURCE_REPO` (owner/repo همین ریپو), `SOURCE_BRANCH` (پیش‌فرض `main`).
1. از **Settings → Networking → Generate Domain** یک دامنه بگیر.
1. یک بار آدرس `https://دامنه‌ات/setup` رو باز کن تا وبهوک تلگرام ثبت بشه.
1. **مهم:** فایل‌سیستم Railway پیش‌فرض ephemeral هست. برای اینکه توکن‌ها/پروژه‌ها بعد
   از هر ریستارت پاک نشن، از **Volumes** یک Volume به مسیر `/app/data` وصل کن
   (یا `DATA_DIR` رو به یه مسیر دیگه تنظیم کن).

## دسترسی: چندکاربره + Clone فقط برای مالک

- **همه می‌تونن از منوی اصلی استفاده کنن** — هرکسی که `/start` بزنه می‌تونه Railway/Cloudflare
  خودش رو وصل کنه و پنل دیپلوی کنه. داده‌ی هرکس (توکن‌ها، پروژه‌ها) کاملاً جدا و فقط زیر
  chat id خودش ذخیره میشه.
- **🧬 Clone Bot فقط برای `ADMIN_CHAT_ID`** — بقیه این دکمه رو توی Advanced نمی‌بینن.
- چون هر کاربر با توکن Railway/Cloudflare خودش کار می‌کنه، منابع خودِ تو مصرف نمیشه.

## 🔒 عضویت اجباری

اگه می‌خوای کاربر قبل از استفاده از بات عضو یک یا چند کانال/گروه بشه، متغیر
`REQUIRED_CHANNELS` رو ست کن:

```
REQUIRED_CHANNELS = "@channel1,@channel2"
```

(روی Cloudflare: `wrangler secret put REQUIRED_CHANNELS` یا توی `[vars]`؛ روی Railway:
Environment Variable معمولی.) هر یوزرنیم رو با کاما جدا کن. بات باید توی اون
کانال/گروه‌ها **ادمین یا عضو** باشه تا بتونه وضعیت عضویت رو چک کنه (`getChatMember`).

اگه کسی عضو نباشه، به‌جای منو یه پیام با دکمه‌ی «عضویت» + دکمه‌ی «✅ عضو شدم، چک کن»
می‌بینه. فقط کانال/گروه عمومی (با یوزرنیم `@...`) پشتیبانی میشه؛ برای پرایوت باید بعداً
لینک دعوت جدا اضافه بشه.

اگه این متغیر خالی/نامشخص باشه، این قابلیت غیرفعاله (پیش‌فرض).

## 🔄 بروزرسانی پنل (Update)

توی صفحه‌ی هر پروژه (📁 My Projects → پروژه):

- **🔄 Update Now** — همون لحظه یک ریدیپلوی می‌زنه که آخرین کامیت ریپوی پنل رو pull می‌کنه.
- **⚪️/🟢 Auto-Update** — با هر بار کلیک روشن/خاموش میشه. اگه روشن باشه، هر روز
  (از طریق cron روی Cloudflare یا `setInterval` روی Railway) خودکار یک ریدیپلوی می‌زنه
  و بهت خبر میده.

روی Cloudflare این از طریق **Cron Trigger** (توی `wrangler.toml`، پیش‌فرض هر روز ۰۳:۰۰ UTC)
انجام میشه. روی Railway چون Cron Trigger نداره، `server.js` خودش هر ۲۴ ساعت
(`setInterval`) همین کار رو انجام می‌ده — یعنی پروسه باید همیشه روشن بمونه (طبیعتاً همینطوره
چون Railway سرویس رو persistent نگه می‌داره).

## 🧬 Clone Bot (فقط مالک)

از Advanced → Clone Bot، اول پلتفرم رو انتخاب می‌کنی:

**☁️ Cloudflare Worker** — ۴ تا چیز می‌پرسه (CF API Token، Account ID، توکن بات جدید،
Chat ID ادمین جدید)، بعد خودش `bot-core.js` + `worker.js` رو از GitHub می‌خونه، باندلشون
می‌کنه، یک KV namespace و یک Worker جدید می‌سازه، webhook رو ثبت می‌کنه.

**🚂 Railway** — ۳ تا چیز می‌پرسه (توکن Railway اکانت مقصد، توکن بات جدید، Chat ID ادمین
جدید)، بعد یک پروژه/سرویس جدید از همون ریپو روی Railway می‌سازه، دامنه می‌گیره، webhook
رو ثبت می‌کنه. (یادت باشه بعدش برای persistent موندن دیتا یک Volume وصل کنی — بات خودش
توی پیام نهایی هم یادآوری می‌کنه.)

## 🗑 حذف پروژه / ♻️ Restart

توی صفحه‌ی هر پروژه:

- **♻️ Restart** — از `serviceInstanceRedeploy` استفاده می‌کنه (همون کامیت فعلی رو دوباره بالا میاره، بدون build جدید).
- **🗑 Delete Project** — یه مرحله‌ی تایید داره («بله، پاک کن» / «نه، بیخیال») چون برگشت‌ناپذیره؛ کل پروژه رو هم از Railway (`projectDelete`) هم از KV پاک می‌کنه.

> ⚠️ نکته درباره‌ی «Stop»: Railway در API عمومیش یک مطلبِ ساده و مستقیم برای «متوقف کردن بدون حذف» نداره (فقط Restart/Redeploy/Delete)، پس این قابلیت فعلاً اضافه نشده تا چیزی حدسی/غیرقابل‌اعتماد نسازیم.

## 📱 QR ورود به پنل

بعد از هر دیپلوی موفق، و همچنین از صفحه‌ی هر پروژه، دکمه‌ی «📱 QR ورود به پنل» یک عکس QR از آدرس دامنه‌ی پنل می‌فرسته (از سرویس عمومی `api.qrserver.com`).

> این QR مربوط به **آدرس ورود به پنل** هست، نه یک لینک اشتراک VLESS/Reality آماده — چون کانفیگ واقعی
> (UUID، پروتکل، Inbound) داخل خودِ پنل ساخته میشه، نه از طریق این بات دیپلوی. اگه بعداً خواستی
> لینک اشتراک واقعی رو هم خودکار بسازه، باید بگی هر پنل دقیقاً از چه فرمتی برای subscription استفاده می‌کنه.

## 📊 Stats + 📣 Broadcast (فقط مالک)

- **📊 Stats**: تعداد کل کاربرهایی که تا حالا `/start` زدن، تعداد اکانت‌های Railway/Cloudflare وصل‌شده، تعداد کل پروژه‌ها، و تعداد پروژه‌های Auto-Update روشن.
- **📣 Broadcast**: متنی که بفرستی رو برای همه‌ی کسایی که تا حالا بات رو استارت کردن ارسال می‌کنه و در آخر گزارش موفق/ناموفق میده. کاربرهایی که بات رو بلاک کرده باشن جزو «ناموفق» حساب میشن.

هر دو مورد فقط زیر `ADMIN_CHAT_ID` قابل‌دسترسیه؛ بقیه اصلاً این دکمه‌ها رو نمی‌بینن.

## 🌐 دامنه‌ی اختصاصی

از صفحه‌ی پروژه → «🌐 دامنه‌ی اختصاصی» → دامنه‌ای که خودت مالکشی رو بفرست. بات از `customDomainCreate`
استفاده می‌کنه و رکوردهای DNS لازم (CNAME + TXT verification) رو برات نشون می‌ده تا خودت توی
DNS provider دامنه‌ت ثبتشون کنی.

## اضافه‌کردن پنل جدید

توی `bot-core.js`، آرایه‌ی `PANELS` رو پیدا کن و یه آیتم جدید اضافه کن:

```js
{
  id: "example",                     // شناسه‌ی کوتاه، بدون : و فاصله
  name: "📦 Example Panel",           // اسمی که توی منو دیده میشه
  repo: "someuser/example-panel",     // owner/repo گیت‌هاب
  buildVars(port) {                   // متغیرهای محیطی موقع ساخت سرویس
    return { PORT: String(port) };
  },
  // promptPort: false,               // اگه پنل خودکار از $PORT استفاده می‌کنه
  // note: "یادداشت بعد از دیپلوی",   // اختیاری، توی پیام نهایی/جزئیات پروژه نشون داده میشه
},
```

|پنل           |ریپو                   |نکته                              |
|--------------|-----------------------|----------------------------------|
|🕷️ Spider Panel|amirh00sain/SpiderPanel|پورت رو از کاربر می‌پرسه           |
|🌐 3x-ui       |x4gpanell/3x-ui        |پورت خودکاره، ورود اول admin/admin|

## چرا دیگه از KV برای state فرم‌ها استفاده نمیشه

سقف واقعی محدودکننده‌ی Cloudflare، ریکوئست Worker نیست — **نوشتن (write) در Workers KV**
هست: پلن رایگان فقط **۱۰۰۰ نوشتن در روز** میده. برای همین، وقتی بات یه سوال متنی می‌پرسه
(`sendPrompt`)، وضعیت فعلی فرم رو به‌صورت یک تگ کوچیک و **قابل‌دیدن** base64
(مثل `{REF:eyJz...}`) ته پیام می‌ذاره و پیام رو با `force_reply` می‌فرسته. وقتی کاربر جواب
می‌ده، تلگرام خودِ پیام قبلی (با تگ REF) رو داخل `reply_to_message` برمی‌گردونه و بات همونجا
state رو دیکد می‌کنه — بدون هیچ خواندن یا نوشتنِ KV.

> نسخه‌ی اول این مکانیزم از کاراکترهای **نامرئی** (zero-width) استفاده می‌کرد، ولی تلگرام
> این کاراکترها رو به‌عنوان اقدام ضدِ اسپم از متن پیام حذف می‌کنه، پس state گم می‌شد. برای
> همین به یک تگ base64 قابل‌دیدن (بی‌ضرر، فقط یه خط فنی زیر هر سوال) تغییر کرد.

KV (یا فایل JSON روی Railway) فقط برای داده‌ای که واقعاً باید دائمی بمونه نوشته میشه:
توکن‌های ذخیره‌شده‌ی هر کاربر و پروژه‌های ساخته‌شده — هرکدوم یک بار در پایان یک فرآیند.

## امنیت

- بقیه‌ی کاربرها (غیر از مالک) هیچ‌وقت دکمه‌ی Clone رو نمی‌بینن و حتی با دستکاری
  callback هم بلاک میشن.
- توکن‌های Railway/Cloudflare هر کاربر فقط زیر chat id خودش ذخیره میشه.
- `WEBHOOK_SECRET` جلوی صدا زدن الکی endpoint توسط بقیه رو می‌گیره.
- توکن‌هایی که موقع فرم تایپ می‌کنی، تا قبل از ذخیره‌ی نهایی به‌صورت base64 (نه
  رمزنگاری‌شده، فقط انکد) داخل تاریخچه‌ی همون چت خصوصی‌ت با بات می‌مونن.
